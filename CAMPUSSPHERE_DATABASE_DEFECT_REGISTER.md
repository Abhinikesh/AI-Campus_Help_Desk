### DB-DEF-003: Historical Announcements with Unlinked `createdBy`
- **Severity:** **P3 (Low)**
- **Collection:** `announcements`
- **Affected Document Count:** 2 documents
- **Affected Records:**
  - Title: `"Midterm Examination Schedule 2026"` (`_id: 6ae70a23882941b291469363`, `createdBy: 6ae70a23ddc55f12504c9e1d`)
  - Title: `"Library Holiday Notice"` (`_id: 6ae70a23882941b2914693ad`, `createdBy: 6ae70a23ddc55f12504c9e1d`)
- **Attribution Protection Findings:**
  - Both documents explicitly store `authorName: "Admin User"` and `authorRole: "admin"` directly in BSON fields.
  - The controller executes `.populate('createdBy', 'name role')` which returns `createdBy: null` without throwing an exception.
  - The frontend components render `ann.title`, `ann.body`, and `ann.createdAt` without crashing.
- **Rejection of Current Administrator Reassignment:** Reassigning `createdBy` to the current administrator `6ae46faf9e9e56f71ecccdd0` is rejected because that administrator did not author these historical notices.
- **Proposed Remediation Options (Phase 3):**
  - **Option 1 (Recommended — Zero Mutation):** Retain records as-is. Original attribution is preserved in `authorName`.
  - **Option 2 (Referential Tombstone):** Insert an archived system user in `users` with ID `6ae70a23ddc55f12504c9e1d` and `name: "Historical Administration (Archived)"` to satisfy strict foreign-key lookups without falsifying user attribution.
